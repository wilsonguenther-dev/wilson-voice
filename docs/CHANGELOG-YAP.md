- YV2: Renamed user-facing "Wilson Voice" → "Yap" (productName, window title, Info.plist display name + permission prompts, tray menu/tooltip, notifications, and all UI copy in desktop/src) while KEEPING the bundle id com.wilsonguenther.wilson-voice and the WilsonVoice data dir so macOS TCC grants and SQLite history persist.
- YV4: Ported the live-reaction pill into the live YappyPill — LIVE escalation WHILE listening (quick→notes→desk→essay by elapsed talk time, showing the matching prop + a tone-aware live line as you go, not just at done), a bigger open capsule (capW 236 / capH 60) with the camera zoomed to ~80% of the buffer so the chick + grass read larger, and slow drifting clouds; keeps the pull-back camera, sky-blue capsule, tier props, and tone-aware done line, all driven by the real recording/audio_level/transcript events.
- YV3: Smart dictation v1 (Wispr parity groundwork) — new pure Rust module `dictation.rs` with `mode_for_app` (frontmost app/bundle → Email/Document/Notes/Code/Chat/Plain) and `format_dictation` (enumerator-cue list detection → numbered list, else prose preserved), 7 unit tests, wired log-only at the transcribe site (source_app → mode) without touching the "never lose text" paste path.
- YV5: Wired smart dictation into the transcribe pipeline — `dictation::resolve_mode` (user-picked fixed mode wins, else `mode_for_app`) + `should_format` gate, then `format_dictation` runs on the transcript BEFORE it is stored/pasted, guarded so a non-empty transcript can never yield empty output (falls back to raw). Added a `dictation_mode` setting (Rust serde default "auto" + TS `dictationMode`) with a pill-style Settings picker (auto|plain|list|email|code|notes) and Rust `#[test]`s proving a fixed mode overrides the detected one and that `format_dictation` is applied.
- YV6: Backtrack v1 (Wispr parity groundwork) — new PURE Rust `clean_backtrack` in `dictation.rs`, called inside `format_dictation` behind the never-lose-text guard: drops standalone fillers ("um/uh/er/erm/hmm") + comma-bounded discourse hedges (", like," / ", you know," / ", i mean,"), and applies unambiguous spoken self-corrections — numeric "actually" restatement ("coffee at 2 actually 3" → "coffee at 3") and clause-retraction markers ("scratch that", "no wait") — while NEVER emptying non-empty input (all-filler utterances return unchanged). Rule-based groundwork for the later local-LLM pass; 5 new `#[test]`s cover filler removal, "actually" restatement, and content preservation.
- YV7: Error logging + diagnostics (support visibility) — new `logging.rs` tees every `env_logger` record to stderr (unchanged console) AND a hand-rolled size-rotating file at `data_dir()/logs/yap.log` (~2 MB, 4 backups), plus a `std::panic::set_hook` that records panic message + location + backtrace to the log. Added a `open_logs_dir` Tauri command (reuses the `open_data_dir` reveal pattern) surfaced as an "Export diagnostics (logs)" button in Settings; a `#[test]` proves rotation caps backups.
- YV8: Distribution packaging — added the `dmg` bundle target (alongside `app`) in tauri.conf.json, wired `tauri-plugin-updater` (Cargo dep + `.plugin(tauri_plugin_updater::Builder::new().build())` + `@tauri-apps/plugin-updater` JS package + a guarded startup `checkForUpdates()`) with a `plugins.updater` config block (GitHub Releases `latest.json` endpoint + a THROWAWAY placeholder minisign pubkey to replace before shipping), granted `updater:default` in the default capability, and added `.github/workflows/release.yml` that on a `v*` tag builds on macos-14 (frontend build + `cargo build --release`), then bundles/signs/publishes the DMG + updater manifest as GitHub Release assets via tauri-action with a notarization step GATED on APPLE_ID/APPLE_PASSWORD/APPLE_TEAM_ID (skips gracefully when absent). Bundle id unchanged (com.wilsonguenther.wilson-voice).
- YV9: First-run onboarding flow — a full-screen React overlay (desktop/src/Onboarding.tsx) with Welcome → live Permissions walkthrough (request_microphone / request_accessibility / polled get_permissions) → Voice calibration (records a prompted phrase via the existing manual_toggle command and keeps it for later personalization) → Done. Gated on a new `onboarded` AppSettings boolean (Rust serde default false + TS interface); shown when !onboarded on launch, set true via saveSettings on finish. Added a "Replay onboarding" button in Settings and a backward-compat serde test. Pill and pipeline untouched.
- YV10: Local-LLM cleanup ARCHITECTURE (no model downloaded) — added an ordered cleanup PIPELINE `dictation::run_cleanup` that runs apply_dictionary → backtrack (`clean_backtrack`) → `format_dictation` → a guarded local-LLM polish stage (`polish_llm`, a documented NO-OP stub that falls back to its input on any error/timeout), with every stage guarded so a non-empty transcript can never become empty. Introduced a `CleanupLevel` (none|light|medium|high) that gates which stages run ("none" = raw passthrough) and a `cleanup_level` AppSettings field (Rust serde default "light" + TS `cleanupLevel` + an Auto-cleanup Settings picker). Wired the pipeline into the transcribe path and now store BOTH texts on the transcript — added a nullable `raw_text` column (idempotent migration) populated with the verbatim ASR output alongside the polished `text`. New `#[test]`s cover level "none" returning raw unchanged, stages running in order, level gating, the guarded LLM no-op, and raw/polished DB storage.
- YV11: Signal hygiene (Tier 0 of docs/research/voice-isolation.md) — three pure, unit-testable DSP functions in `record.rs` applied to the mono buffer at the NATIVE rate BEFORE the 16 kHz downsample: `high_pass` (2nd-order RBJ Butterworth high-pass at 80 Hz to kill DC/hum/rumble), `normalize_rms` (RMS soft-AGC toward -20 dBFS, peak-limited so a boosted quiet voice never clips, with a silence guard that leaves near-silent captures untouched and a final hard limit to [-1,1]), and `edge_fade` (5 ms linear fades to de-click the PTT press/release). Each returns its input unchanged on empty/zero-rate/degenerate input or if it would ever produce a non-finite sample, so a bad clip can never NaN or empty the pipeline. Device setup and the resampler are untouched; pill/pipeline unchanged. Six new `#[test]`s prove a ~-40 dBFS sine lifts to within a few dB of target with no sample exceeding 1.0, the high-pass attenuates a 25 Hz tone >12 dB while preserving 300 Hz within ~1 dB, silence is left unchanged, and the full chain never yields NaN/empty.
- YV12: Denoise with nnnoiseless (Tier 1 of docs/research/voice-isolation.md) — added the pure-Rust RNNoise crate `nnnoiseless` (BSD-3, no shipped model asset) and a guarded `denoise_rnnoise` in `record.rs` that runs over the whole mono clip AFTER the Tier-0 hygiene chain and BEFORE the 16 kHz downsample: it resamples to RNNoise's native 48 kHz if needed, streams 480-sample (10 ms) frames through `DenoiseState` (scaling to/from the i16 range RNNoise expects), flushes the one-frame overlap-add delay so the output re-aligns with the input, then resamples back. Conservative by construction — on any degeneracy (empty, zero-rate, sub-frame, non-finite) or if it would collapse the signal (output RMS < 5% of input) it returns the input UNCHANGED so a real utterance is never lost. Gated behind a new `denoise` AppSettings bool (Rust serde default true + TS `denoise` + a Settings toggle), read at capture start and threaded through `start_recording`/`record_loop`. Three new `#[test]`s prove segmental SNR improves ≥ 6 dB on a voiced+broadband-noise fixture, clean speech loses ≤ 1 dB of energy, and every fallback path returns the input unchanged.
- YV13: Settings overhaul — regrouped the Settings screen into five plain-language sections (Companion, Dictation, Shortcut, Model & Speed, Privacy & Diagnostics) with a new `.settings-section` header style, surfaced the three most-used controls near the top (Pill style + Dictation mode + Denoise), and rewrote developer-jargon copy (dropped Metal/RAM/AWS/RNNoise/"glass HUD"/"verbatim" wording) into friendly language. Every existing setting stays wired and saving — no keys removed (model, language, autoPaste, pttBinding, showFloatingPill, pillStyle, dictationMode, cleanupLevel, denoise, onboarded all still referenced); TypeScript + CSS only, no Rust or pipeline changes. tsc clean, cargo test 54/54.
- YV14: Insights charts — exposed the analytics series to the UI via two new Tauri commands (`daily_series(days)` / `monthly_series(months)`) wrapping the existing authoritative `daily_stats` rollups in `db.rs` and registered in the `generate_handler`, then rendered three hand-rolled, zero-dependency visualizations in the Insights view (no chart lib / no CDN): a DAILY WORDS bar chart (inline `<svg>`, last 30 days), a GitHub-style ACTIVITY HEATMAP (inline `<svg>`, last 365 days laid into weekday-aligned week columns, color-scaled by words with a Less→More legend), and a WORDS-BY-MONTH bar list (last 12 months). Each has a graceful empty state and hover `<title>` tooltips; the existing stats/latency/top-apps panels are untouched. Series load in `refreshAll` + `refreshInsights` so charts stay live after mutations. tsc clean, cargo test 54/54.
- YV15: Configurable hotkey — added a real "Set shortcut" key-capture control to the Settings → Shortcut panel (frontend-only; the CGEvent fn/fn⌃ engine in `ptt_macos.rs` and `lib.rs::save_settings` are untouched). The preset chips (fn⌃ / fn / fn / fn⌃) stay as quick options and now share a single `applyBinding(id)` helper that sets `pttBinding` + keeps `hotkeyLabel` in sync. The new control arms a global `keydown` listener (`capturing` state) that records the next combo the user holds, validates it, and maps it to a SUPPORTED binding: a Control-inclusive combo → `fn_control` (Control is the reliably web-detectable half of the fn⌃ gesture), the fn/Globe key → `fn`, with Esc to cancel. Unsupported presses (a bare letter, or a Cmd/Alt/Shift-only combo the engine can't wire) are reported via a live `captureHint` message instead of being persisted, and the fn mapping surfaces the emoji-picker system-conflict tip. No arbitrary-key custom path is faked because the CGEvent engine only binds fn-family keys end-to-end; the persisted value is always fn | fn_control | both. tsc clean, cargo test 54/54.
