A mutation that killed NOTHING, and what was done about it
--------------------------------------------------------------
The first attempt at MUTATION 22 (drop the uncertainty guard) left all 18
tests green: every fixture in this file is arithmetically exact, so no
measurement in it was ever inside its own resolution and the guard was
untested production code — the same class this phase's YV108 review flagged
on an untested `track ASC` tiebreak. Rather than delete the finding, the
fixture it needed was written: `with_pairing_slack` stamps the ±10 ms that
really does sit between a record's `host_ns` (the LAST anchor's stamp) and its
`captured_samples` (the whole block's count), and
`a_perfect_crystal_measured_past_the_band_by_its_own_slack_is_not_flagged`
lands at -122.3 ppm on a device that never drifted. MUTATION 22 above is the
re-run against that fixture.

A second dead mutation ("accept a run with zero kept intervals") was answered
by DELETING the code instead: the `.filter(intervals > 0)` it targeted was
unreachable — a run with no kept intervals has a zero span and was already
caught by the `TRUE_RATE_MIN_SPAN_SECONDS` gate — so there is now one gate for
"not enough to stand behind" rather than two that could disagree.
