- YV11: Signal hygiene (Tier 0 of docs/research/voice-isolation.md) — three pure, unit-testable DSP functions in `record.rs` applied to the mono buffer at the NATIVE rate BEFORE the 16 kHz downsample: `high_pass` (2nd-order RBJ Butterworth high-pass at 80 Hz to kill DC/hum/rumble), `normalize_rms` (RMS soft-AGC toward -20 dBFS, peak-limited so a boosted quiet voice never clips, with a silence guard that leaves near-silent captures untouched and a final hard limit to [-1,1]), and `edge_fade` (5 ms linear fades to de-click the PTT press/release). Each returns its input unchanged on empty/zero-rate/degenerate input or if it would ever produce a non-finite sample, so a bad clip can never NaN or empty the pipeline. Device setup and the resampler are untouched; pill/pipeline unchanged. Six new `#[test]`s prove a ~-40 dBFS sine lifts to within a few dB of target with no sample exceeding 1.0, the high-pass attenuates a 25 Hz tone >12 dB while preserving 300 Hz within ~1 dB, silence is left unchanged, and the full chain never yields NaN/empty.
- YV12: Denoise with nnnoiseless (Tier 1 of docs/research/voice-isolation.md) — added the pure-Rust RNNoise crate `nnnoiseless` (BSD-3, no shipped model asset) and a guarded `denoise_rnnoise` in `record.rs` that runs over the whole mono clip AFTER the Tier-0 hygiene chain and BEFORE the 16 kHz downsample: it resamples to RNNoise's native 48 kHz if needed, streams 480-sample (10 ms) frames through `DenoiseState` (scaling to/from the i16 range RNNoise expects), flushes the one-frame overlap-add delay so the output re-aligns with the input, then resamples back. Conservative by construction — on any degeneracy (empty, zero-rate, sub-frame, non-finite) or if it would collapse the signal (output RMS < 5% of input) it returns the input UNCHANGED so a real utterance is never lost. Gated behind a new `denoise` AppSettings bool (Rust serde default true + TS `denoise` + a Settings toggle), read at capture start and threaded through `start_recording`/`record_loop`. Three new `#[test]`s prove segmental SNR improves ≥ 6 dB on a voiced+broadband-noise fixture, clean speech loses ≤ 1 dB of energy, and every fallback path returns the input unchanged.

- YV16: Kill the "WPM-SERV" spam — a near-silent / sub-second hotkey tap made Whisper hallucinate degenerate repetitive tokens ("WPM-SERV-SERV-SERV…") that Yap then PASTED into the focused app. Root cause: `RecordingResult.speech_seconds` fell back to raw clip length when energy-VAD voiced < 0.1s (so a silent clip looked non-silent), nothing gated ASR on real speech, and no guard caught degenerate ASR output before paste. Fixed with two pure, unit-tested guards wired into `stop_and_transcribe`. (1) NO-SPEECH GATE: added a separate `voiced_seconds: f64` field to `RecordingResult` in `record.rs` carrying the TRUE energy-VAD value (0.0 on silence, NO clip-length fallback — `speech_seconds` still floors for the WPM denominator), read by a pure `dictation::has_enough_speech(voiced_seconds)` (0.35s threshold) that skips ASR on a fumbled tap. (2) HALLUCINATION REJECT: `dictation::is_hallucinated_repetition(&str)` flags degenerate Whisper loops — ≥4 consecutive identical tokens, or unique/total token ratio < 0.3 when total ≥ 6, or a single token that is a short unit repeated ≥4× when split on `-`/`_` (the "WPM-SERV-SERV-SERV" case) — while staying conservative for normal prose, real numbered lists, and short emphatics ("no no no"). In `lib.rs` the inner closure now returns `Result<Option<…>>`: `None` (no speech before ASR, or a rejected hallucination after ASR) shows a gentle soft status + `paste_outcome` flash ("Didn't catch any speech — hold and speak"), clears `busy`, does NOT paste, does NOT insert a transcript, and does NOT set a hard `last_error`. record.rs DSP and the pill are untouched. Five new `#[test]`s; cargo test 60/60, tsc clean.

(M3) Stop leaking voice WAVs on error: `stop_and_transcribe` (`lib.rs`) previously deleted `rec.wav_path` only on the success and gate paths, so an ASR or DB `?` failure left the user's `.wav` on disk forever — replaced all the scattered deletes with a single RAII `WavCleanup` drop-guard created right after `stop_recording`, so the clip is unlinked on EVERY exit (success, no-speech/hallucination gate, and the error early-returns). (M4) Take HuggingFace offline on warm launches: `asr.rs::apply_env` now always sets `HF_HUB_DISABLE_TELEMETRY=1`, and sets `HF_HUB_OFFLINE=1` whenever the selected model's snapshot already exists in the HF cache (threaded the model through `with_daemon`/`spawn_daemon`; a new pure `hf_snapshot_present` checks `<hub>/models--…/snapshots/<rev>/`), so a warm run makes ZERO huggingface.co calls while first-run download still reaches the network; `asr_worker.py` also `setdefault`s `HF_HUB_DISABLE_TELEMETRY=1`. - YV21: Auto-paste only into the app you dictated into (audit M1) — closed a wrong-target paste / privacy leak. `source_app` is captured at key-release, but the auto-paste (synthesized ⌘V) runs 1–3s later inside the ASR thread; `focus::should_auto_paste()` only checked that the frontmost ELEMENT is a text field, never that the frontmost APP is still the one dictated into — so switching apps during the ASR delay pasted the transcript into the WRONG app. Fixed in `paste.rs`: `copy_and_maybe_paste` now takes the dictation-time `source_app`, and immediately before synthesizing ⌘V it samples the CURRENT frontmost app (`focus::frontmost_app_name()`) and only pastes when a new pure, unit-tested helper `is_same_paste_target(source_app, current_app)` positively confirms the same app is still frontmost (case/whitespace-tolerant; unknown or different identity = mismatch). On mismatch it falls back to clipboard-only with a gentle status ("Copied — you switched apps, so I didn't paste") — the transcript is always copied first, so text is never lost and never lands in another app. The dictation path in `lib.rs` passes `source_app`; the explicit `paste_entry` re-paste passes `None` (current frontmost IS the intended target, no guard). One new `#[test]`; cargo test 62/62, tsc clean.

- YV23: Security surface — shrink the attack surface before wider distribution (audit M5/M7). (M5) Removed the two dylib-injection entitlements — `com.apple.security.cs.allow-dyld-environment-variables` and `com.apple.security.cs.disable-library-validation` — from the MAIN APP's `Entitlements.plist`. On a non-sandboxed process that holds Accessibility trust and synthesizes keystrokes, those two together let `DYLD_INSERT_LIBRARIES` load an attacker dylib into Yap and inherit its TCC grants (a privilege-escalation path). MLX/JIT runs in the SEPARATE Python child with its own signature, and setting env vars for that child via `Command.env()` needs no dyld entitlement, so the main app never needed them; it still codesigns with hardened runtime (kept `allow-jit` + `allow-unsigned-executable-memory` for the WebKit/Tauri JS engine, plus `audio-input`), launches, dictates, and auto-pastes. (M7) Removed three registered-but-never-used Tauri plugins — `tauri_plugin_opener::init()`, `tauri_plugin_shell::init()`, and `tauri_plugin_store` — from `lib.rs` (folders/logs open via `std::process::Command("open")` and settings persist via SQLite/`settings.json`, not these plugins; no Rust or frontend code calls them), dropped their `tauri-plugin-opener` / `tauri-plugin-shell` / `tauri-plugin-store` deps in `Cargo.toml` (Cargo.lock regenerated), and revoked the matching `opener:default`, `shell:allow-open`, and `store:default` capability grants in `capabilities/default.json`. tsc clean, cargo test 62/62.
