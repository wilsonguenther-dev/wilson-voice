YV128 revise-first fix — non-vacuity evidence for
`serde_deserialisation_cannot_bypass_the_normalising_constructor`

The BLOCKING finding: `NormalizedEmbedding` derived `Serialize, Deserialize`
with `#[serde(transparent)]`, which generates a SECOND constructor that skips
`NormalizedEmbedding::new()` — no L2 normalisation, no finite check, no empty
check, no zero-norm check. That falsifies the module header's "NormalizedEmbedding
is the ONLY way to hand this module a vector, its constructor is the
normalisation" and `Centroid::updated_with`'s "`sample` is already unit-length
(it cannot be anything else)".

Fix as shipped: derive dropped; `Serialize` hand-written as a plain forward (it
cannot break an invariant the value already holds); `Deserialize` hand-written to
deserialise into `Vec<f32>` and then route through `NormalizedEmbedding::new()`,
turning a refused vector into `serde::de::Error::custom`. The seam YV129 needs to
parse the sidecar's `{"embedding": [...]}` therefore exists AND validates, rather
than being removed and re-added as a derive by the next person in a hurry.

Each mutation below was applied to the fixed tree, the test run, then reverted.
`grep -c MUTATION desktop/src-tauri/src/speaker_profiles.rs` = 0 on the pushed head.
