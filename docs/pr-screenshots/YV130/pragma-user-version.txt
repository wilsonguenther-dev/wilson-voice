YV130 — the migration ladder, read off a real file

The backlog's acceptance line says `PRAGMA user_version` returns 7. It
returns 5, and the deviation is forced rather than chosen — see
MIGRATION_5_SEGMENT_ATTRIBUTION's doc comment. YV130's section was written
expecting YV126 (cluster_index, step 5) and YV128 (speaker tables, step 6)
to have landed first. Neither has: both are open PRs, and this branch is cut
from main, whose ladder tops out at 4. run_migrations walks one rung at a
time and breaks on a missing arm, so a build stamped 7 over holes at 5 and 6
would log an error at 5 and create none of this. The next free rung is the
only rung that works. YV128's branch made the same call for the same reason.

actually wrote.
