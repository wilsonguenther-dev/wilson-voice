YV120 review fix — the tuning transcript for the acoustic speaker-distinctness gate
Run on macOS 15 (aarch64), rustc 1.94.0, 2026-08-15.

WHY THIS FILE EXISTS
--------------------
The first cut of this item shipped two diarization fixtures in which all six
"speakers" were one voice. `synthesize()` hardcoded `const VOICE = "Samantha"`
and took no voice argument; `generate_room_3` threw the per-speaker voice away
(`let _ = voice;`) and `generate_classroom_6` never bound it (`_voice`). The only
per-speaker difference left in the audio was a scalar gain — which is exactly the
quantity an L2-normalised cosine embedding is invariant to — so fixture (e), the
fixture YV126's clustering threshold is meant to be tuned against, carried no
separable speaker identity at all.

The gate that was supposed to catch that read meta.json's `voice` STRINGS, which
the generator wrote from the same table it ignored. It passed. This file is the
measurement behind its replacement, which reads the audio.

THE CONSTANT
------------
    const MIN_SPEAKER_F0_RATIO: f64 = 1.12;

A RATIO and not a difference in Hz, because this estimator resolves F0 by picking
an integer autocorrelation lag: its resolution is f^2/rate, ~0.8 Hz at 80 Hz and
~13 Hz at 320 Hz. A fixed Hz floor would be far too lax at the bottom of the band
and nearly unsatisfiable at the top, and would push the roster toward voices that
differ in Hz rather than voices that differ.

  tightest measured pair on the shipped corpus   1.185x   (fixture (f), spk_e/spk_f)
  the floor                                      1.120x
  the corpus this replaces                       1.000x   (fixture (e), spk_a/spk_b)
  estimator resolution at 250 Hz                 ~1.032x

So the floor sits comfortably below what ships, comfortably above the estimator's
own noise, and fails the corpus it was written to catch.

WHAT THIS GATE DOES NOT CLAIM
-----------------------------
F0 is a weak proxy for speaker identity. Two voices an embedding separates easily
can share a fundamental, and this check would not notice. It is not trying to
predict CAM++ distances — YV126 measures those, against this corpus, with the
model. What it proves is the one thing that was actually wrong: that the rendered
audio carries per-speaker variation which survives the L2 normalisation a cosine
embedding ends with, instead of only the scalar gain, which does not. It costs
about two seconds, needs no model bytes and no network, and reads the samples
rather than the metadata.
