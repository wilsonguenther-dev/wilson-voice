## Reading the detector results (instrument notes, not UI findings)

- The `silent-empty` hits on **Onboarding step 1** (both sizes) and **Settings** (both
  personas, both sizes) are cases the detector was not built for. A welcome card and a
  settings form are not lists. They are recorded here so nobody "fixes" them by weakening
  condition 5. The Settings row below gives the structural fix: mark each settings card
  `data-row`.
- The `silent-empty` hit on **Scratchpad / daily** is a real structural gap. One note is
  rendered, but its list item carries no row marker, so the detector cannot tell a
  populated list from an empty one (see the Scratchpad row).
- **Model download**: the shim rejects `download_model`, so the first-run "Preparing your
  speech engine…" ribbon never moves. A headless run cannot measure how slow the real
  download is. The Onboarding row records only what is visible, which is a ribbon with no
  size, percentage or error.
- **Permissions view**: the ledger schema has no Permissions screen, so its findings are
  filed under **Settings** with view file `desktop/src/views/Permissions.tsx`.
- The pill is out of scope for this walk (yap24-PILL owns its states).

## Out of scope (new feature)

- An in-app "what's new / first dictation" guided tour after onboarding is skipped. Today
  Home has no first-take walkthrough, and building one is a new capability, not a fix to
  `Home.tsx`.
- A live download speed and time estimate for the model would need a new progress event
  field from Rust (bytes/s). O1 above covers only showing what already arrives.
- Showing Settings sub-tabs (Advanced, Audio, Companion, Dictation, License, Privacy,
  Shortcut, Snippets) per tab in the smoke would need a tab-walk mode in the driver. This
  walk captured only the default tab.
